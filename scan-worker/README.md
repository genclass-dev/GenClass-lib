# genclass-scan: the genclass.dev page check

Type an address, and a Cloudflare browser loads that one page as a desktop and a phone, light and dark, runs visual
checks, then types into the search box and double-clicks a submit button with the GenClass runtime watching. The page
shows a score out of 100 with its breakdown, screenshots with numbered boxes, every finding with what was measured and
a suggested fix, what the race probe tried and what GenClass saw, with and without guard mode.

- **Test copy:** `https://genclass-scan.mehar-144.workers.dev/scan` (workers.dev only; deployed from this directory).
- **Routes it will own on genclass.dev** (not live; the owner adds them after review): `genclass.dev/api/scan*` and
  `genclass.dev/scan*`. The more specific `/api/scan*` route wins over the telemetry worker's `genclass.dev/api/*`.
- **genclass.dev/&lt;url&gt;** (`genclass.dev/example.com`, `genclass.dev/https://example.com/pricing`): the site worker
  hands a path to this worker as `/scan?url=<path>` over the service binding `SCAN`, only when no page or asset answered
  (404), for GET/HEAD, when the path is URL-safe and starts with `http(s):` or is a hostname with an IANA TLD
  (`site/src/scan-path.js`, tested against every published file in `site/check/scan-path.test.mjs`). This worker
  answers the same path form itself on workers.dev.

## Routes

| route | what |
|---|---|
| `GET /scan` | the URL box |
| `GET /scan?url=…` | the report page: the cached report if one is younger than 6 hours, else it starts a scan from the page |
| `GET /scan/about` | what the scanner does and never does, the user agent, limits, the score formula and weights, opt-out, retention |
| `POST /api/scan {url}` | JSON for refusals (400 address, 403 opt-out or robots, 409 same address in progress, 429 rate, 503 busy) and cache hits (`{ ok, cached, report }`); otherwise `application/x-ndjson`: `{type:"progress",step}` lines, then `{type:"done",report}` or `{type:"error",code,message}` |
| `GET /api/scan/report?url=…` | the cached report or 404 |
| `GET /api/scan/shot/<key>/<id>-<view>.jpg` | a screenshot (from R2) |
| `GET /api/scan/health` | `{ ok, ua, runtime }` |

Every HTML response has `x-robots-tag: noindex, nofollow`, a per-response CSP nonce (`default-src 'none'`, one inline
script and one inline style, fonts from Google Fonts, images from this origin and genclass.dev), no third-party
scripts, and puts all dynamic text in place with `textContent` from a `<script type="application/json">` block.

## What happens on POST /api/scan

1. **Address** (`src/target.ts`): https:// added when missing; http and https only; credentials and fragment stripped;
   default ports only; IP literals refused in every form (decimal, hex, octal, short, IPv6 incl. mapped, NAT64, 6to4),
   with the reason for private, loopback, link-local, CGNAT and metadata ranges; `localhost`, `*.local`, `*.internal`,
   `*.test` and other reserved names refused; genclass.dev and the genclass workers refused; the host needs an IANA TLD
   (`src/tlds.ts`, generated by `scripts/update-tlds.mjs`); IDNs become punycode; trailing dots dropped.
2. **Cache**: a report younger than 6 hours for the same normalised URL is returned as is (R2 `scans/reports/<key>.json`).
3. **Opt-out**: `scans/blocklist.json` (`{ "hosts": [...] }`, subdomains included) plus the `BLOCKLIST` variable.
4. **Rate limit**: `SCAN_LIMIT`, 5 new scans per 60 s per client (a hash of the IP, never stored).
5. **DNS**: A and AAAA over DNS-over-HTTPS; a name that resolves into a blocked range is refused; fails closed.
6. **robots.txt**: only a group naming `GenClassScan` counts (a person asked for one page); redirects followed by hand
   and checked; a missing file allows the scan.
7. **Slots**: at most `MAX_CONCURRENT` (3) scans at once across everyone, and one per address, as compare-and-swap
   leases on `scans/slots.json` (expire after 75 s by themselves).
8. **Scan** (`src/scan.ts`), 45 s hard budget, against Browser Rendering (`@cloudflare/puppeteer` 1.4.0):
   - three views in parallel: desktop 1366×768 light, phone 390×844 light, phone 390×844 dark
     (`prefers-color-scheme`); user agent: a Chrome UA ending in `GenClassScan/1.0 (+https://genclass.dev/scan)`;
     navigation capped at 20 s, then up to 4 s for the page's network to go quiet (the scanner's own runtime and model
     downloads do not count);
   - the visual checks (`window.__genclassScanChecks`, below), a JPEG of the top of the page, a box for every finding;
   - the race probe on the desktop page with `@genclass/runtime` 0.2.1 injected before any page script (observe,
     `telemetry: false`, model from `https://genclass.dev/model/@genclass/runtime-model@0.2.0/files/`): type `a`, `ab`,
     `abc` 80 ms apart into the first search-like input, then double-click the most prominent submit button of a
     same-origin form that would POST (forms with password or card fields are skipped); `rt.on("detect")` and
     `rt.on("act")` are recorded with each decision's gate and reason; if the model is not ready in time the report
     says so;
   - the same probe in a fresh page with GenClass in guard mode, waiting for the same targets.
9. **Report** (`src/report.ts`), saved to R2 with the screenshots, streamed to the page.

### The request policy (`src/policy.ts`), in every view and phase

- No non-GET request reaches the network: POST, PUT, PATCH, DELETE and beacons get a local `200` JSON (CORS headers
  for the page's origin), a form navigation gets `204` so the page stays, preflights get `204`.
- Requests to blocked hosts (literal checks) are aborted, redirect hops included; main-frame redirects are also
  DNS-checked.
- After the first load the main frame never navigates (the probe does not follow links).
- While clicking, fetch/XHR/document GETs to other origins are aborted (nothing submitted to a third party by GET).
- During the probe, fetch/XHR GETs get 0 to 1,500 ms of extra latency from a seeded sequence (longest first in a
  burst), so responses can arrive out of order. Service workers are not allowed to register, and WebSocket sends are
  held while the probe types and clicks.

## Visual checks and the visual-chunk interface

`src/checks.ts` is the built-in subset the scanner ships while the GenClass visual checks (`packages/runtime/src/visual`,
branch `wave2/visual`) are not built: images that loaded with no data, failed stylesheets and fonts (network status
≥ 400 or a failed load, and `document.fonts` errors), template leaks (`undefined`, `NaN`, `[object Object]`,
`{{...}}` in visible text outside code), text under 1.5:1 contrast on a solid known background (hit-tested in bands
of one viewport over the captured height; text over images, gradients, video, blend modes or backdrop filters is
skipped and tallied in `checks.contrastSkipped`), sideways scrolling on the phone views (against the device width when
the page has a viewport meta tag), and first-screen controls whose centre point hits another element (dialogs and
consent banners are noted, not counted).

The interface a built chunk must provide (injected before the built-in subset, which then steps aside):

```ts
window.__genclassScanChecks(options: { view, phone, deviceWidth, failedImages, captureHeight, max })
  -> { findings: { kind, selector, box: { x, y, w, h } | null, measured, detail }[], notes: string[], page: {...} }
window.__genclassScanFixes?(findings) -> { applied: { kind, selector, how }[] }   // optional: the opt-in fixes
```

`kind` is one of the kinds in `src/catalog.ts`. `scripts/build-visual.sh <checkout of wave2/visual>` bundles the
chunk into `src/visual-source.ts` (run it on CI or a VM, not on the owner's Mac). With fixes present, the guard page
turns them on, re-runs the checks, and a finding counts as fixed only when the re-check no longer finds it.

## The score and the with-GenClass column

`score = 100 − Σ_category min(25, Σ points)`, with 10, 5 or 2 points by severity (`src/score.ts`, published on
`/scan/about`). The same element with the same problem in several views counts once. Deterministic: the same findings
give the same score.

The with-GenClass score is computed from measured fixes only (`raceFix` in `src/report.ts`: fewer requests sent in the
guard pass, none identical, and a GenClass action on record; visual fixes only after a re-check) and shown only when
`WITH_GENCLASS=on`. It is **off** in this build: the runtime ships no visual fixes yet. The race probe section always
shows the measured guard comparison and, when GenClass held back, its gate and reason.

## Configuration (`wrangler.jsonc` vars)

| var | default | what |
|---|---|---|
| `MAX_CONCURRENT` | `3` | scans at once across everyone |
| `WITH_GENCLASS` | `off` | `on` shows the with-GenClass score column |
| `GUARD_HOLD_MS` | `900` | `policy.holdBudgetMs` in the guard pass (the WASM model's decisions take 180 to 450 ms here) |
| `GUARD_AGGRESSIVENESS` | unset = `balanced` | the guard pass's profile; the report names it |
| `GUARD_MARGIN` | unset | `policy.thresholds.guard` (a gain margin) for the guard pass; the report calls it a demo setting |
| `BLOCKLIST` | unset | extra opted-out hosts, comma-separated |
| `PUBLIC_ORIGIN` | genclass.dev on genclass.dev, else this origin | base of share links |

Bindings: `BROWSER` (Browser Rendering), `BUCKET` (R2 `genclass-telemetry`, `scans/` prefix only), `SCAN_LIMIT`
(rate limit, namespace 4810). Hourly cron `23 * * * *` deletes `scans/shots/` and `scans/reports/` objects older than
24 hours (`sweep` in `src/store.ts`); no R2 lifecycle rule was added.

## Tests

```bash
cd scan-worker && npm ci && npm run typecheck && npm test     # node:test with type stripping (Node >= 22.18)
node --test site/check/scan-path.test.mjs                     # the site worker's genclass.dev/<url> rule (from the repo root)
```

`test/target.test.ts` (normalisation, IPv4/IPv6 forms, IDN, trailing dots, userinfo, DNS, robots), `test/policy.test.ts`
(non-GET answered locally, blocked hosts and redirect hops aborted, no navigation, no third-party submits, latency),
`test/report.test.ts` (score caps, determinism, merging, fixes only when measured), `test/checks.test.ts` (colour,
contrast, leak matching, injected sources), `test/app.test.ts` (the HTTP surface with the browser mocked: refusals in
order, rate limit, cache, slots, a full streamed scan with the interception outcome of every request, screenshots,
report escaping, the path form, the sweep), `test/tlds.test.ts` (the two TLD copies and path rules agree). CI job:
`scan-worker` in `.github/workflows/ci.yml`.

`test/fixture/` is a test page with one of each problem on purpose (`genclass-scan-fixture.mehar-144.workers.dev`).

## End-to-end runs (2026-10-13, test copy, Chrome 128 in Browser Rendering)

Three public pages, chosen to cover the range, and the fixture. Sites are not named; the findings describe one load of
one page with these checks, nothing more. Times are the scanner's own measurements in ms (launch / three views in
parallel / observe probe / guard pass).

| page | total | launch / views / probe / guard | score | findings | GenClass model (WASM, q8) | race probe |
|---|---|---|---|---|---|---|
| Site A: a plain static page | 12.9 s | 1,153 / 4,047 / 2,666 / 4,754 | 100 | 0 | ready, loaded in 3.4 s | nothing to probe: no search box, no form that posts |
| Site B: a JavaScript-heavy app | 15.0 s | 1,268 / 4,758 / 2,973 / 5,831 | 100 | 0 | ready, 2.7 s | typed into its search box: 0 requests while typing; no form that posts |
| Site C: a site made with an AI app builder, from the builder community's public showcase | 14.5 s | 740 / 4,310 / 3,460 / 5,796 | 100 | 0 | ready, 1.8 s | double-clicked its form's submit button: 0 requests (the page's own code stopped the empty submit) |
| Fixture: deliberate problems | 22.7 s | 766 / 5,511 / 7,446 / 8,783 | 40 | 7 | ready, 2.0 s | 3 typeahead requests, answered out of order (3, 1, 2); 2 identical POSTs from one double click |

What these runs show, plainly:

- The fixture's seven deliberate problems were each found once (merged across the three views): text at 1.08:1,
  `Total: NaN`, a 404 stylesheet, a 404 image, a 640 px box that makes the page 680 px wide on a 390 px phone, a link
  under a transparent layer, and the double submit.
- On the fixture, GenClass in observe mode flagged the second POST as a duplicate at 99% confidence. In guard mode at
  the shipped `balanced` gates it **did not act**: coalesce scored a gain of 2.85 to 3.02 against a margin of 4 (3 with
  `eager`), so 2 requests were still sent. With the home-page lab's demo setting (`GUARD_MARGIN=0`,
  `GUARD_AGGRESSIVENESS=eager`, one run with `WITH_GENCLASS=on`) guard coalesced it: 1 request sent instead of 2, the
  with-GenClass score was 50 against 40. The deployed test copy uses the shipped gates.
- The three public pages had no findings from these checks. The contrast check is conservative and skips text it cannot
  measure: on Site C it measured 1 of 17 text elements in the captured area (9 over images or gradients, 6 under
  backdrop filters, 1 clipped background), on Site B 12 of 24. Site A has no viewport meta tag; the report notes that
  phones show it zoomed out at 980 px.
- 21 scans in all while building this (Sites A to C, the fixture eight times, eight other public pages): every one
  finished between 7.3 and 23.7 s, none near the 45 s budget. Of the 11 public pages, one had a finding (a web font that
  failed to load, score 98); the others scored 100. One JavaScript-heavy page answered HTTP 403 to the automated browser
  (bot protection) and was replaced for Site B; the report shows such a page as it was served.
