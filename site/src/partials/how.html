01

Observe

Instruments fetch, XHR, WebSocket, EventSource, DOM events, errors, storage and timers, and links async work into causal chains.

02

Learn

Builds per-operation baselines for latency, failure and request rate, and relations that keep holding, like total == sum(price × qty).

03

Triage

Computes facts for every write and request. Only a response over newer data, a repeat, a failure streak or a broken relation goes to the model.

04

Decide

An 8.8M-parameter model (8.1M encoder, 0.7M heads) in a Web Worker reads the situation and returns a calibrated diagnosis and action.

05

Act, if you opt in

Only in guard or heal mode, and only when acting beats doing nothing by the margin of the profile you chose: cautious, balanced or eager. At the shipped setting that is rare: under 8% of the cases where acting would help.

06

Explain

Every call is logged in plain English. rt.explain(id) returns the exact text the model read, and reversible actions can be undone.

Closing the loop, coming next: GenClass finds the bug on the deployed app. The MCP server hands the finding, with its evidence and the pages affected, to your coding agent. The agent fixes it. After the fix ships, GenClass reports whether the problem came back. The MCP server reads only what the genclass.dev collector already keeps; it never feeds the runtime, the model or the gate, and the runtime carries none of it. Run it on your own machine, free; Individual runs it for you on genclass.dev; Enterprise runs it inside your own network. The closed loop.
