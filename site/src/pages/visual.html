Bugs your users can see, with no error to log.

Unreadable text, broken images, layouts that break on phones, "undefined" on the page, buttons under an invisible layer. They render without an exception, so no error monitor records them. GenClass measures them on the page and names the element, what was measured, and a fix.

What it finds

Every family of visual bug in the catalog, drawn.

The collects what breaks on screen in AI-built sites, from studies, builder forums, code searches and audits, and ranks each bug by how strong the evidence is that it is common. These are its families, in its order. Under each: the measured checks for that family, by the names their reports use. A family's other bugs have no check yet.

How it works

Measured checks, a trained model, and fixes you turn on.

01

Measure in the browser

Each check is a measurement against a documented threshold, or a fact the browser reports: text below 1.5:1 contrast against a solid background, an image's error event, a page wider than the phone showing it. A report names the element, the value measured and the threshold, and suggests a CSS change for that selector. Text over photos and gradients is skipped, not guessed.

Fix only when you ask

Observe mode reports and never changes the page. With visual fixes turned on in guard or heal mode, three narrow fixes can run: a readable text colour, a leaked pointer-events: none removed from body, a stuck scroll lock released. Each is measured again after it runs, and each can be undone.

Design and thresholds: . The checks never feed the network model, and neither the checks nor the visual model read pixels.

Limits

What it does not do yet.

  • No pixels. Text over photos, video and gradients is skipped, and canvas and WebGL content is not checked.
  • Only what the visitor's browser shows. In your app, the checks run in the colour scheme, width and hover state each visitor is using. The page check adds a phone view and dark mode.
  • Two checks need Chromium. Layout shifts and failed CSS background images have no browser signal elsewhere.
  • Not an accessibility audit. Readable text below WCAG AA contrast is not reported, and nothing here makes a site accessible or WCAG compliant.
  • Design quality is not reported as a bug. Uneven alignment and spacing are in the catalog; no check reports them.
  • It does not repair CSS in general. The three fixes above are the only changes it can make, and only when you turn them on.
