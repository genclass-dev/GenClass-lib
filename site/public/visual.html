Home/Visual bugs

Bugs your users can see, with no error to log.

Unreadable text, broken images, layouts that break on phones, "undefined" on the page, buttons under an invisible layer. They render without an exception, so no error monitor records them. GenClass is testing checks that measure them on the page and name the element, what was measured, and a fix.

What it findsResults

In testing. The visual checks are not in runtime 0.2.1: they are built and in testing for a later release. The page check, which scans one public page, is not open yet. The model is planned and has no published numbers yet. Its results are due by October 14, 2026, 22:00 UTC.

What it finds

Every family of visual bug in the catalog, drawn.

The GenClass catalog of visual bugs collects what breaks on screen in AI-built sites, from studies, builder forums, code searches and audits, and ranks each bug by how strong the evidence is that it is common. These are its families, in its order. Under each: the measured checks for that family, by the names their reports use. A family's other bugs have no check yet.

How it works

Measured checks, a planned model, and opt-in fixes.

01

Measure in the browser

Each check is a measurement against a documented threshold, or a fact the browser reports: text below 1.5:1 contrast against a solid background, an image's error event, a page wider than the phone showing it. A report names the element, the value measured and the threshold, and suggests a CSS change for that selector. Text over photos and gradients is skipped, not guessed.

02

Learn from crawled pages

A model is planned, to be trained on a crawl of AI-built and regular sites with faults injected from outside each page, so every example has a known label. Its recall and false reports will be published below, with the data and the split.

03

Fix only when you ask

In testing: observe mode reports and never changes the page. With visual fixes turned on in guard or heal mode, three narrow fixes can run: a readable text colour, a leaked pointer-events: none removed from body, a stuck scroll lock released. Each is measured again after it runs, and each can be undone.

The checks never feed the network model, and they read no pixels.

Results

Results due by October 14, 2026, 22:00 UTC.

The model is planned and nothing about it has been measured, so this section is empty on purpose. When the results are in, it shows:

  • Recall per bug family at two false-report rates, 0.1% and 1%, with the number of test examples behind each.
  • Precision on pages with no injected faults, the share of reports on ordinary pages that are real bugs.
  • Size and cost: the download, and the time per element on a named device.
  • Where each number comes from: the crawl, the data, how it was kept apart from training, and a link to the results.
Limits

What it does not do yet.

  • The model has no numbers yet. Nothing on this page claims a detection rate until one is measured and published.
  • No pixels. Text over photos, video and gradients is skipped, and canvas and WebGL content is not checked.
  • Only what the visitor's browser shows. Once they ship in the runtime, the checks run in your app in the colour scheme, width and hover state each visitor is using.
  • Two checks need Chromium. Layout shifts and failed CSS background images have no browser signal elsewhere.
  • Not an accessibility audit. Readable text below WCAG AA contrast is not reported, and nothing here makes a site accessible or WCAG compliant.
  • Design quality is not reported as a bug. Uneven alignment and spacing are in the catalog; no check reports them.
  • It does not repair CSS in general. The three fixes above are the only changes it can make, and only when you turn them on.
