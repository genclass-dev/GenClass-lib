Home/Visual bugs

Bugs your users can see, with no error to log.

Unreadable text, broken images, layouts that break on phones, "undefined" on the page, buttons under an invisible layer. They render without an exception, so no error monitor records them. GenClass measures them on the page and names the element, what was measured, and a fix. Paste an address to run the checks on one public page.

What it finds

Every family of visual bug in the catalog, drawn.

The GenClass catalog of visual bugs collects what breaks on screen in AI-built sites, from studies, builder forums, code searches and audits, and ranks each bug by how strong the evidence is that it is common. These are its families, in its order. Under each: the measured checks for that family, by the names their reports use. A family's other bugs have no check yet.

How it works

Measured checks, a model still in evaluation, and opt-in fixes.

01

Measure in the browser

Each check is a measurement against a documented threshold, or a fact the browser reports: text below 1.5:1 contrast against a solid background, an image's error event, a page wider than the phone showing it. A report names the element, the value measured and the threshold, and suggests a CSS change for that selector. Text over photos and gradients is skipped, not guessed.

02

Learn from crawled pages

A learned model is still being trained and evaluated on a crawl of AI-built and regular sites, with faults injected from outside each page so every example has a known label. It has no published numbers yet. If it meets its bar, its recall and false reports will be published on this page with the data and the split. GenClass Vision, a separate model that reads screenshot crops, gives the page check a second opinion as a beta (below).

03

Fix only when you ask

In testing: observe mode reports and never changes the page. With visual fixes turned on in guard or heal mode, three narrow fixes can run: a readable text colour, a leaked pointer-events: none removed from body, a stuck scroll lock released. Each is measured again after it runs, and each can be undone. On the unmodified pages of the bench, 0 fixes were applied in 128 page views.

Design and thresholds: the visual checks design. The checks never feed the network model, and they read no pixels.

GenClass Vision

A 4.8 MB model that looks at the crop.

In the page check, GenClass Vision v2 (beta) looks at the screenshot crop of each measured visual finding and gives it a score from 0 to 1. It never changes a finding or the score. Every number here is from its results.

  • Level with Clef on ranking. Average precision 0.611 on 1,052 held-out crops (173 real), against 0.615 for Cloudflare's Clef (27B parameters) and 0.651 for OpenAI's Decisions API (gpt-6-luna, public beta), which taught it.
  • Behind the measured rules, 48% real. Of 500 test crops the rules flagged (15% real), it kept 69; 33 were real.
  • Small and fast. 4.8 MB, 1.19 M parameters, 0.53 ms a crop on one CPU thread (AMD EPYC 9V45, onnxruntime 1.31, one crop at a time).
  • A beta. The labels come from AI labeller agents (Claude subagents), not people. No bug family reached the 60% precision bar, so nothing it says is scored.
Limits

What it does not do yet.

  • The learned model has no numbers yet. Nothing on this page claims a detection rate for it until one is measured and published.
  • Measured on GenClass's own apps and 31 to 34 of 40 public home pages per run. Recall is on faults planted in the author's own forms, and the public sites were also used to tune the checks between runs, so they are not held out.
  • No pixels. Text over photos, video and gradients is skipped, and canvas and WebGL content is not checked.
  • Only what the visitor's browser shows. Once they ship in the runtime, the checks run in your app in the colour scheme, width and hover state each visitor is using. The page check adds a phone view and dark mode.
  • Two checks need Chromium. Layout shifts and failed CSS background images have no browser signal elsewhere.
  • Not an accessibility audit. Readable text below WCAG AA contrast is not reported, and nothing here makes a site accessible or WCAG compliant.
  • Design quality is not reported as a bug. Uneven alignment and spacing are in the catalog; no check reports them.
  • It does not repair CSS in general. The three fixes above are the only changes it can make, and only when you turn them on.
